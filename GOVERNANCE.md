# Governance

## Claim-to-action chain

`EVIDENCE → ASSUMPTIONS → METHOD → REASONING → UNCERTAINTY → VALIDITY → CONCLUSION → AUTHORITY → ACTION`

Every transition must be reconstructable from the report and audit log.

## Approval rule

No completed analysis authorises an action. Without explicit approval, the final status is `REQUEST_HUMAN_REVIEW`. The V1 `--approve` flag records approval for the bounded demonstration only. There is deliberately no customer-contact, credit, pricing, eligibility, or other external execution connector.

## Safe-stop rules

The workflow stops when the task asks for an unsupported problem type, causal language from observational predictive data, a required schema field is absent, target encoding is invalid, or provenance hashes fail. The duration leak is a critical but repairable issue because the feature is removed before training.

## Human reviewer questions

Before any real deployment, a reviewer must determine lawful basis and consent, intended population, current data validity, prohibited uses, protected characteristics, vulnerability impacts, contact capacity, error costs, escalation, opt-out, monitoring, rollback, and accountable owner. V1 supplies none of those permissions.
